# Telegram Bot 无回复排查 SOP：从网关到限流到记忆

> 这是过去一个月 171 个运维会话里出现频率最高的故障（约占 1/4）。修一次，写成 SOP，后人不再踩。

## 排查顺序（别跳步）

1. **网关活着吗**：`systemctl status` 看 Bot 网关进程，有没有死、有没有在重启循环。
2. **限流了吗**：查日志 `rate-limit / 429`，撞限流先降频、排队，别急着重启。
3. **鉴权过期了吗**：token / API key 是否过期或被轮换，重新签发后更新配置。
4. **模型过期了吗**：上游模型下线或改名会导致静默失败，切可用模型验证。
5. **记忆层坏了吗**：跨会话记忆（如 Honcho）迁移/损坏时，Bot 常表现为“收到但不回”，清空或重建记忆再测。

## 为什么值得写成 SOP

单次排查平均烧掉半小时，全是重复劳动。五步走完仍无解，再开新会话深挖；五步内解决的，直接记一条日志，不占用长会话。
