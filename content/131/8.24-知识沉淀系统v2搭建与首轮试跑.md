# 8.24 知识沉淀系统 v2 搭建与首轮试跑

> 本文是本次对话的原始归档（最低优先级）。长期价值已沉淀到 `100_Wiki/知识沉淀/decisions.md`（D1–D5）与 `knowledge.md`（K1–K5）。

## 背景

- 旧方案：每次 AI 对话 → 写流水账总结 → 存 `20_对话笔记/<日期>/`，长期堆积无效信息。
- 目标：只沉淀有长期价值的东西，并让下一次 AI 能快速复用（"让未来的 AI 少走弯路"）。

## 本次做了什么

1. **归档清理 100_Wiki**（以最新为准 + 剃刀定律）：
   - 归档：Tencent 日报 v1、Hermes工作流契约、公众号发布流水线（旧本机链路）、LLMWiki 重复目录 → `000_Raw/90_历史归档/100_Wiki清理_2026-08/`
   - 保留：Tencent 当前版、8.8 Hermes对齐指引、知识库自动化、VPS/x-ui、网络与安全、开发环境
   - 修复 15 处死链（200_Rules、交接报告、02_成果、8.6 笔记）
2. **建总索引** `100_Wiki/INDEX.md`：项目清单 + 各项目 INDEX 路径。
3. **建项目 INDEX**：`100_Wiki/知识沉淀/INDEX.md`、`100_Wiki/公众号/INDEX.md`（用户手动建目录，我配 INDEX）。
4. **改 skill v2**：`obsidian-save`（先判断、只写增量、宁可少存）装到全局 `~/.codex/skills/` + `~/.config/opencode/skills/`（两份一致）；库内副本已删。
5. **全局 AGENTS.md**：确认保持 shell 契约单一职责（知识库规则不进 AGENTS，全部收进 skill）。
6. **项目级 AGENTS 映射**：`000_Raw/10_项目/公众号/AGENTS.md` → 指向 `100_Wiki/公众号/INDEX.md`（试点）。
7. **首轮试跑**：在本次对话内完整执行工作流（认路 → 判断 → decisions.md / knowledge.md → INDEX 更新 → 本文归档）。

## 关键决策（详见 decisions.md）

- D1 先判断、只写增量，宁可少存
- D2 项目目录只由用户手动创建，skill 绝不自动新建
- D3 成品归产出项目、方法归工作流、不复制只链接
- D4 沉淀规则放 skill，全局 AGENTS 保持单一职责
- D5 项目级 AGENTS 映射，试点=公众号
