# 9.3 MindFS 模型同步修复（AI Toolbox → 腾讯云）

> 原始归档。结论与方法见 [[100_Wiki/知识沉淀/knowledge#K7 MindFS 模型同步：文件落地≠UI 生效|K7]]、[[100_Wiki/知识沉淀/decisions#D7 联网 AI 运维不给全 root，用"白名单天花板"|D7]]。

## 背景

- Windows AI Toolbox 以 mindfs（124.222.*.*）向腾讯云同步 Codex/OpenCode/pi 配置，
  报 `打开远程文件失败 /opt/mindfs-data/.codex/config.toml: Permission denied`。
- 根因：`/root/.codex` 等是软链到数据盘的单源目录，root 裸跑 Codex 后文件变成
  `root:root 600`，mindfs 写不进。

## 做的事（2026-09-03，一个会话内完成）

1. 备份 + `chown -R -h mindfs:mindfs` 三棵树（约 1.3 万文件，多为 `.codex/.tmp` 插件缓存
   与 opencode `node_modules`，真配置仅几十个），`config.toml/auth.json` 设 600。
2. 新建 5 分钟巡逻 `mindfs-perm-fix.timer`（root 脏文件自愈，已实测）。
3. 新建 `codex-mindfs` 应急包装（注：重沙箱任务仍受限，因 vendor 二进制在 hermes 私有目录下）。
4. 白名单提权 `/etc/sudoers.d/mindfs-ops`（修权限/查重启自家服务/只读诊断），加 `systemd-journal` 组，
   允许/拒绝实测通过；拒绝给 `ALL`（见 D7）。
5. 同步成功后 UI 仍显示 GPT-5.x：确诊 15:55 启动的 app-server 因当时文件被锁而回退默认；
   用官方 `POST /api/agents/restart` 重拉 codex/opencode，`GET /api/agents` 验证
   codex=11 新模型、opencode=32（`192/…`）。生产 8 服务全程 active。
6. 阶段二只做手动：一键脚本 `/usr/local/bin/mindfs-sync-refresh`（已全流程实测），
   SOP `/opt/mindfs-data/SYNC-MODELS-SOP.md`，sudoers 追加 `MINDFS_REFRESH`。
   自动刷新砍掉（同步周期按月计，手动触发）。

## 待办/注意

- 用户在 MindFS 新开 Codex/OpenCode 会话确认模型下拉（旧会话钉老模型）。
- `pi` 在 `/api/agents` 显示不可用（改动前已存在，未排查）。
- Claude Code 入口隐藏未做：服务端无官方隐藏开关，方案待定（UI 收藏/默认优先）。
