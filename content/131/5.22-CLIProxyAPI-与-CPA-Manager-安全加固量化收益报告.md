# CLIProxyAPI 与 CPA Manager 安全加固量化收益报告

生成时间：2026-05-22 00:01 UTC

## 1. 报告范围

本报告量化对 CLIProxyAPI 与 CPA Manager 相关入口采取安全加固前后的变化和收益，重点覆盖：

- `cpa` 业务入口管理路径探测变化。
- `cpam` 管理入口源站直连绕过风险变化。
- CLIProxyAPI 应用层是否收到管理路径探测。
- 敏感路径拦截、攻击告警、自动封禁带来的运营收益。

报告只使用脱敏统计和聚合结果，不包含密钥、Cookie、Authorization、query string、原始日志整行或业务数据。

## 2. 关键加固动作

| 类别 | 加固动作 | 直接目标 |
| --- | --- | --- |
| 管理入口认证 | 为 `cpam` 管理入口接入 Cloudflare Access Email OTP | 防止未认证访问管理页面 |
| 源站防绕过 | `cpam` 源站仅允许可信代理来源访问 | 防止绕过 Cloudflare 直连源站 |
| 业务入口隔离 | `cpa` 业务入口禁用 `/v0/management` 管理 API | 防止业务入口承载管理接口 |
| 历史入口处理 | `cpa` 旧管理页面重定向到受保护管理入口 | 收敛历史管理入口 |
| 高危下载阻断 | 禁用管理端认证文件下载路径 | 降低凭据或认证材料泄露风险 |
| 敏感路径拦截 | 对 API/status 入口增加 `.env`、`.git`、WordPress、Actuator 等扫描路径拦截 | 减少扫描路径 fallback 与误暴露 |
| 准实时告警 | 新增 Caddy 攻击告警 systemd timer | 将攻击发现从人工巡检缩短到分钟级 |
| 自动封禁例外 | 对非 Cloudflare 来源且携带 `cpa-batch` 的 CPA 管理路径扫描直接封禁 | 降低已确认恶意批量探测的重复命中 |

### 3.1 对比切点

| 切点 | 时间 | 用途 |

| `cpa-batch` 自动封禁切点 | 2026-05-21 11:27:12 UTC | 对比特征化批量扫描前后变化 |

### 3.2 日志范围

| 日志组 | 保留日志时间范围 | 说明 |
| --- | --- | --- |
| `cpa` Caddy access log | 2026-05-19 13:08:12 UTC 至 2026-05-21 23:04:23 UTC | 可用于源站防绕过切点前后对比 |

### 3.3 口径说明

- 管理路径：`/v0/management` 及其子路径，另包括历史管理页面 `/management.html`。
- `2xx/3xx` 在统计中归为“非拒绝响应”，但 `308` 属于跳转信号，不代表数据泄露或管理操作成功。
- 内部来源 `172.23.0.1` 的 `curl` 请求按本机验证噪声处理，不作为外部攻击成功证据。
- `cpam` 加固前的源站直连证据来自处置时人工确认：外部来源曾可直连拿到管理页面 `200`，管理 API 返回 `401`；加固后直连被 `403` 阻断。

## 4. 量化对比结果

### 4.1 `cpa` 业务入口管理路径扫描显著下降

以源站防绕过加固切点为界，`cpa` 业务入口管理路径命中变化如下：

| 指标 | 加固前 | 加固后 | 变化 |
| --- | ---: | ---: | ---: |
| 统计窗口长度 | 11.07 小时 | 46.87 小时 | 后窗口更长 |
| 管理路径命中数 | 100 | 35 | 绝对数量下降 65% |
| 管理路径命中速率 | 9.033 次/小时 | 0.747 次/小时 | 下降约 91.7% |
| 直接来源命中数 | 100 | 35 | 下降 65% |
| `2xx/3xx` 非拒绝响应数 | 95 | 28 | 下降约 70.5% |
| `403` 拒绝数 | 5 | 7 | 拒绝占比提升 |

状态码分布：

| 状态码 | 加固前 | 加固后 | 解读 |
| --- | ---: | ---: | --- |
| `308` | 95 | 28 | 主要是旧入口/HTTP 到 HTTPS 的跳转，不等同于得手 |
| `403` | 5 | 7 | 管理 API 拒绝逐步成为主要防线之一 |

主要路径变化：

| 阶段 | 高频路径 | 次数 | 说明 |
| --- | --- | ---: | --- |
| 加固前 | `/v0/management/api-keys` | 97 | 典型管理 API 探测集中命中 |
| 加固后 | `/v0/management/api-keys` | 28 | 仍有探测，但频率显著下降，且未进入应用层 |
| 加固后 | `/management.html` | 3 | 历史入口探测残留 |
| 加固后 | `/v0/management` | 2 | 低频探测残留 |

结论：`cpa` 业务入口的管理路径探测从每小时约 9 次下降到每小时约 0.75 次，降幅约 91.7%。剩余命中主要是自动化扫描残留，未见进入 CLIProxyAPI 应用层的证据。

### 4.2 `cpa-batch` 批量探测被快速压制

以 `cpa-batch` 自动封禁上线为切点，批量探测变化如下：

| 指标 | 自动封禁前 | 自动封禁后 | 变化 |
| --- | ---: | ---: | ---: |
| `cpa-batch` 管理路径请求数 | 122 | 1 | 下降约 99.2% |
| 来源数量 | 30 | 1 | 下降约 96.7% |
| `308` 跳转响应 | 120 | 0 | 跳转类探测基本消失 |
| `403` 拒绝响应 | 2 | 1 | 后续命中直接拒绝 |

加固前高频来源按网段脱敏后集中在多个云主机/代理网段，表现为横向批量探测特征。自动封禁后，仅观察到 1 次后续命中，且返回 `403`。

结论：针对已确认恶意特征 `cpa-batch/1.0` 的专项封禁收益非常明显，请求量下降约 99.2%，来源数量下降约 96.7%，剩余命中未获得有效响应。

### 4.3 `cpam` 管理入口源站直连绕过被阻断

`cpam` 当前保留日志主要覆盖加固后窗口，因此无法仅靠当前滚动日志完整还原加固前全量基线。但处置过程中已确认过关键事实：

| 阶段 | 现象 | 风险判断 |
| --- | --- | --- |
| 加固前 | 外部来源可绕过 Cloudflare 直连源站访问管理页面并得到 `200` | 存在源站绕过外层认证风险 |
| 加固前 | 同一类直连访问管理 API 得到 `401` | 未见无需认证直接读取管理 API 的证据 |
| 加固后 | 非可信代理来源直连 `cpam` 返回 `403` | 源站绕过路径被阻断 |
| 加固后 | 当前保留日志中外部直连成功数为 0 | 未见加固后外部绕过成功证据 |

加固后 `cpam` 管理入口仍有大量 `200` 管理 API 请求，主要来自经过认证/代理链路的正常管理使用。当前统计窗口内，仅看到 2 次直接来源记录，来源为 Docker 内部网关 `172.23.0.1`，属于本机验证噪声，不是外部绕过攻击。

结论：`cpam` 的核心风险从“外部可直连源站触达管理页面”降低为“非代理来源被 Caddy 直接拒绝”。加固后未见外部来源绕过 Cloudflare 成功访问管理入口。

### 4.4 CLIProxyAPI 应用层未收到管理路径探测

CLIProxyAPI 应用日志中管理路径命中统计：

| 阶段 | 应用层管理路径命中 | 说明 |
| --- | ---: | --- |
| 加固前 | 0 | 未见管理探测进入应用层 |
| 加固后 | 0 | 加固后仍未进入应用层 |

`api` 与 `status` 入口存在少量管理路径形态请求，但来源为内部 `172.23.0.1` 的 `curl` 验证请求，按本机测试噪声处理。

结论：当前证据显示，外部管理路径探测主要停留在 Caddy 入口层，没有打到 CLIProxyAPI 应用层。这说明反代层隔离与路径拒绝规则对保护应用层有效。

### 4.5 敏感路径拦截降低 fallback 和误暴露风险

对 `api` 与 `status` 入口补充敏感路径拦截后，以下类型探测在入口层被统一收敛：

- 环境变量文件：`/.env`、`/.env*`。
- Git 元数据：`/.git/*`。
- WordPress 探测：`/wp-login.php`、`/xmlrpc.php`、`/wp-config.php`。
- 运行状态探测：`/server-status`、`/phpinfo`、`/actuator*`。
- 常见漏洞路径：`/vendor/phpunit*`、`/cgi-bin/*`。
- SSH/云凭据路径：`/.ssh/*`、`/.aws/*`、`/id_rsa`。

收益不只是减少请求数量，而是避免单页应用 fallback 或默认路由把明显扫描路径返回 `200`，从而降低误判、信息暴露和后续攻击者重试价值。

## 5. 告警与封禁收益

### 5.1 攻击发现从人工巡检缩短到分钟级

新增攻击告警链路后，原本需要人工查看 Caddy 日志或等待每日巡检的事件，现在由 systemd timer 每分钟增量扫描并发送 Telegram 告警。

| 能力 | 加固前 | 加固后 | 收益 |
| --- | --- | --- | --- |
| 攻击发现 | 人工排查/每日巡检 | 分钟级准实时告警 | 缩短发现时间 |
| 日志处理 | 人工筛选原始日志 | 自动解析 JSON access log | 降低排查成本 |
| 告警内容 | 依赖人工描述 | 脱敏摘要：级别、规则、对象、来源网段、次数 | 降低敏感信息传播面 |
| 去重 | 无系统去重 | 按规则、对象、来源、状态桶去重 | 减少刷屏 |
| 日报衔接 | 只做系统体检 | 汇总近 24 小时攻击告警 | 形成趋势复盘 |

### 5.2 当前告警数据解读

当前告警摘要中记录过：

| 告警类型 | 数量 | 解读 |
| --- | ---: | --- |
| `management_path_not_rejected` | 9 | 早期按 `3xx` 也升为 CRIT，后续已调整为仅 `2xx` 为 CRIT、`3xx` 为 WARN |
| `cpa_batch_auto_banned` | 1 | 已确认恶意特征触发自动封禁 |

说明：历史 9 条 CRIT 主要来自规则初版把 `308` 跳转也视为 CRIT。现已修正为：

- 管理路径 `2xx`：CRIT。
- 管理路径 `3xx`：WARN。
- 管理路径 `4xx`：不按“未拒绝”告警。

调整后告警更贴合风险：跳转代表探测和暴露信号，但不等同于读取成功。

### 5.3 fail2ban 联动收益

当前 `fail2ban` 已具备管理路径专项封禁能力：

| jail | 当前封禁 | 累计封禁 | 说明 |
| --- | ---: | ---: | --- |
| `caddy-management` | 1 | 10 | 专项处理管理路径探测来源 |
| `recidive-extended` | 61 | 451 | 长周期重复恶意来源治理 |

收益：明确恶意来源不再只进入观察队列，而是进入专项封禁或长周期封禁，降低重复扫描噪音和后续误触发概率。

## 6. 风险是否“得手”的判断

基于当前证据，未看到攻击者成功读取管理数据或进入 CLIProxyAPI 应用层管理逻辑的证据：

| 证据项 | 结果 | 判断 |
| --- | --- | --- |
| CLIProxyAPI 应用层管理路径命中 | 0 | 未见管理探测进入应用层 |
| `cpa` 管理 API 探测 | 主要为 `308/403` | 有扫描，未见数据读取成功 |
| `cpam` 加固前 API 直连 | `401` | 未见未认证 API 读取成功 |
| `cpam` 加固后外部直连 | `403` | 源站绕过被阻断 |
| 高危下载路径 | 加固后预期拒绝 | 未见成功下载证据 |
| 敏感路径 | 已入口层拦截 | 降低 fallback 暴露风险 |

结论：当前更符合“存在明确恶意扫描和管理路径探测，但未看到得手证据”。主要收益是将风险从“可能绕过外层认证触达源站管理页面”降到“入口层拒绝、告警、封禁、日报复盘”。
