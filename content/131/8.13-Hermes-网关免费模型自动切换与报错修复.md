# Hermes 网关免费模型自动切换与报错修复（2026-08-13）

## 一、部署目标与约束

- 在 **yun1**（`121.41.*.*`，admin）与 **tencent**（`124.222.*.*`，root）两台云服务器部署 Hermes Agent 网关。
- 绑定 **Nous 官方免费账号**，使用免费 API token 模型；两个独立免费额度账号（不是同一账号）。
- 配置 Telegram（bot token 来自 `@telegram BOT.txt`）：hermes1=yun1，hermes2=tencent。
- egress 走 **sing-box 代理** `127.0.0.1:7890`（参考本地 NAS jp `192.168.*.*` 的配置同步）。
- **硬约束（不可违反）**：不得影响 tencent 既有容器服务（omniroute/codex-box 等）；不得影响 yun1 的 `ai-chat` 前后端容器。

## 二、最终落地配置（两台一致）

`/opt/data/config.yaml`（**注意路径，见坑 3**），属主 `hermes:hermes`，权限 `600`：

```yaml
model: tencent/hy3:free
model_catalog:
  enabled: true
  url: https://hermes-agent.nousresearch.com/docs/api/model-catalog.json
  ttl_hours: 1
  providers: {}
fallback_model:
  provider: nous
  model: stepfun/step-3.7-flash:free
```

- 服务：`hermes-gateway.service`（`User=hermes`，`HERMES_HOME=/opt/data`，`WorkingDirectory=/opt/data`，`EnvironmentFile=/opt/data/.env`）。
- `/opt/data/.env`（600，hermes）：含 `HTTP_PROXY/HTTPS_PROXY=http://127.0.0.1:7890`、`NO_PROXY=localhost,127.0.0.1,::1`、`TELEGRAM_BOT_TOKEN=xxxx`、`TELEGRAM_ALLOWED_USERS=5359999791`。

## 三、踩过的坑（关键经验）

### 坑 1：Nous 登录非交互时自动导入共享凭证
- `hermes auth add nous --type oauth --no-browser` 检测到 `<HERMES_HOME>/shared/nous_auth.json` 存在时，在管道/非 TTY 输入下 `input()` 抛 `EOFError` 被当作 "y"，自动 rehydrate 共享凭证 → 绑定成错误账号。
- **修复**：删 `/opt/data/shared/nous_auth.json`（及 `.lock`）后再跑，才会走 device-code 流程打印新 `user_code` 链接。
- 最终两个账号独立：yun1 `org_id=nas_organisation:246f1c47-…`、tencent `org_id=nas_organisation:bda55a46-…`（均不同于最初误导入的 `cmopzccfr…`）。

### 坑 2：免费模型名写错
- 误写 `tencent/hy3-preview:free` → Nous 推理 404「Model not found」。
- **正确**：`tencent/hy3:free`（直连 `https://inference-api.nousresearch.com/v1/chat/completions` 返回 200 "PONG"，不计费）。Nous 可用模型共 363 个；`tencent/hy3-preview:free` 不存在，`stepfun/step-3.7-flash:free` 存在。

### 坑 3（本次主因）：配置放错路径 → 网关回退付费默认模型
- **现象**：用户通过 Telegram 发消息，bot 回复 `⚠️ The model provider failed after retries`；日志真实报错：
  `404 Model 'deepseek/deepseek-v4-flash' requires available credits … pick a free model.` —— 网关在用**付费模型**，免费账号无额度。
- **根因**：网关 `_load_gateway_config()` 读取 `_hermes_home / 'config.yaml'`（即 `/opt/data/config.yaml`，源码 `gateway/run.py` 约 1530 行）；而之前把配置建在了 `/opt/data/.hermes/config.yaml`（那是 CLI `load_config()` 的路径）。网关读不到 → 回退内置默认 `deepseek/deepseek-v4-flash`（付费）→ 404。
- **修复**：把配置写到正确路径 `/opt/data/config.yaml`，删除误放的 `/opt/data/.hermes/config.yaml`，重启 `hermes-gateway.service`。
- **佐证**：jp 的配置文件就在 `/opt/data/config.yaml`（无 `.hermes` 那份），与网关加载路径一致。

## 四、jp 的「免费模型自动切换」机制（已复刻到云上）

- `model_catalog`：Hermes 每小时拉取 Nous 的当前免费/推荐模型清单（`/api/nous/recommended-models` 的 `freeRecommendedModels` 是「当前免费模型」真相源），供模型选择器感知最新免费款。目录 URL 实际 301 重定向到 `nousresearch.github.io/.../model-catalog.json`，经代理返回 200 有效 JSON。
- `fallback_model`：主模型调用失败时自动回退到另一个 `:free` 模型（`stepfun/step-3.7-flash:free`）。
- **局限（与 jp 一致）**：网关主模型是静态值。当 `tencent/hy3:free` 不再免费时，回退到 `fallback_model`（固定免费款），而非自动跟到「当月最新免费款」；严格跟最新款需在切换后手动 `hermes model` 重选（catalog 已让选择器显示最新款）。
- **注意**：日后若用 `hermes model` 等 CLI 改模型，必须 `export HERMES_HOME=/opt/data`，否则 CLI 会在未设 HERMES_HOME 时于 `~/.hermes/config.yaml` 生成影子配置、与网关读取的 `/opt/data/config.yaml` 不一致。
