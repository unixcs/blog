# 8.9 公众号自动发布工作流部署

## 可复用信息




### 架构决策 + 选型理由

- **选 peterpan/wechat-publisher-skill（Node 单文件）做唯一推送出口**，而非 md2wechat 自带发布：微信 access_token 是"最新才有效"，多工具同时碰微信接口会互相作废 token（实测反复出现 40001）。收敛成单出口后，唯一属主写草稿/传素材。
- **选 md2wechat 只做 humanize（去AI味），不做 convert 排版**：免费版 `convert --mode ai` 需 API key，且免费仅 3 个基础主题；humanize 免费返回 `action_required` + prompt，由 LLM 执行重写即可，核心卖点是"聚焦省心"。
- **选 gzh-design 做排版合规门**：输出必须带 `<span leaf="">` 包裹（否则粘贴公众号后样式整片丢失），有确定性校验脚本 `validate_gzh_html.py`，ERROR 清零才算完成。6 套主题从 `references/theme-index.md` 选。
- **排版（gzh-design）与推送（peterpan）分离**：gzh-design 只生成 HTML 到本地，peterpan `publish-file` 接受 `.html` 并透传（parseHtmlFile 只提取 title/images，不改样式）。

### 关键命令 / 路径（jp 服务器）

- 工具目录：`/opt/data/skills/`（wechat-publisher / gzh-design / wechat-publish-workflow）
- 凭证：`/opt/data/.wechat-publisher/config.json`（chmod 600）；数据目录需 `export WECHAT_PUBLISHER_DATA_DIR=/opt/data/.wechat-publisher`
- peterpan 推送：`node wechat-publisher.mjs publish-file <html> --title <T> --digest <D> --thumb <cover>`
- md2wechat 去AI味：`md2wechat humanize <file> --intensity=medium`（**必须等号形式**，空格形式报 `accepts 1 arg(s)` bug）
- 排版校验：`python3 /opt/data/skills/gzh-design/scripts/validate_gzh_html.py <html>`
- 编排 skill：`/opt/data/skills/wechat-publish-workflow/SKILL.md`（铁律 + 双路径 + 错误码速查）
- jp 侧 Hermes：systemd 服务 `hermes-gateway.service`，非容器；WSL 侧管理文档 `/mnt/vps/jp/AGENTS.md` 已同步更新

### 踩坑记录

- **npm 装 md2wechat 失败**：postinstall 从 GitHub Releases 下 arm64 二进制，网络慢被超时截断且无报错；手动 `curl -C -` 断点续传 + checksums.txt 校验和比对解决（aarch64 专用）。
- **40001 invalid credential 反复出现**：根因是 access_token 缓存与微信服务器端不同步（多客户端刷新互作废）。处置：删 `/opt/data/.wechat-publisher/token.json` 后重试即可。
- **封面必填**：草稿 `thumb_media_id` 缺失会报 40013，必须先用 `upload-cover` 上传永久素材取 media_id 再传 `--thumb`。
- **个人订阅号无 freepublish 权限（48001）**：只能建草稿，群发须人工到公众号后台操作，这是能力上限不是故障。
- **出口 IP 白名单**：jp 出口 IPv4 固定，用户已在微信后台放行，无需代理中转；若换网络需重新核对 40164。

### 工作流 SOP（v4 双路径）

- 路线一（默认）：写稿 → 用户确认 → `md2wechat humanize` 去AI味 → gzh-design 排版 → validate 0 ERROR → peterpan publish-file 推草稿 → 回读 round-trip → 用户手动群发
- 路线二（可选）：跳过 humanize，直接排版推送
- 铁律：单推送出口、排版合规门、封面必填、去AI味必做、初稿先经用户确认

## 对话摘要

用户需求：搭建公众号自动创作发布流水线（写稿→去AI味→排版→推送草稿箱），个人订阅号，混合触发模式，并给 AppID/Secret + 白名单放行，要求完成后复核再验收。

执行摘要：三轮子代理评审定稿 v4；在 jp 部署 wechat-publisher（peterpan）、md2wechat CLI、gzh-design 三个 skill + 编排 skill；实测 free 版 humanize 行为、校验脚本、token 排障；端到端真实创建草稿并 round-trip 回读全部通过；复核（凭证安全/工具可用/skill 完整/回读）全 PASS。

结果：完结。验收测试草稿《用 Hermes 搭公众号自动发稿流水线》已留在草稿箱供后台核对样式，可删；后续正式发稿由 Hermes 按 workflow skill 执行，初稿仍须用户确认后才推送。
