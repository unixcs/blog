# M.d 8.5 公众号推送SOP与封面撑高bug修复

## 目标与背景
把一篇 Markdown 文章排版后推送到微信公众号草稿箱，并沉淀成可复用流水线。
本次核心任务有两段：
1. 修复"封面大卡片被微信撑高成 3:2"的 bug（本地打开是正常 1:2）。
2. 用子代理做对抗式审查，把整条链路打磨成可复用、安全的版本。

前置：用 `gzh-design` skill（moyu-green 主题）把 Markdown 排版成公众号合规 HTML。
平台约束（不变）：只认内联 style + `<span leaf="">` 包文本；禁 `<style>/<script>/<div>/class/id/float/grid/@media` 等。

## 关键结论
- **封面撑高的根因（第一性原理）**：微信公众号会把 HTML **标签之间的换行/空白**渲染成约 28px 高的空行（继承根容器 `line-height:1.75`），层层叠加把卡片撑高。下方 4 张滑动卡因在 `white-space:nowrap` 内而免疫。
- **修复点**：不让"生成"产物变丑，而是让"负责跟微信打交道的推送步骤"保证传入内容无换行——`push_gzh_draft.py` 上传前自动 `re.sub(r'>\s+<','><',html)` + `re.sub(r' {2,}',' ',html)`。生成产物可保持可读，微信永远拿到干净版。**不单独做"去空白脚本"（剃刀原则）**。
- **对抗审查 13 项发现**，核心已修：
  - 严重①：封面图默认取正文首图，而本文首图是 AI 生成的"掀翻美国 AI 大佬"图，当信息流封面跑题+合规风险 → 已在 push 增加 `COVER_URL` 第 4 参数解耦（图由用户后续给）。
  - 严重②：`validate_gzh_html.py` 不查标签间空白，压实正则若被误删会无声复发 → 已在 validate 加 `>\s*\n\s*<` / `>\s{2,}<` 的 WARNING。
  - 中等③：push 硬编码 TITLE/DIGEST → 已改为参数化 `push_gzh_draft.py <html> <标题> [摘要] [封面URL] [作者]`。
  - 中等④：cleanup 误传 media_id 会删光同名草稿 → 已加"误传校验拒绝" + 必须 `--yes` 才真删（默认预览）。
  - 中等⑤：2 份早期错标题废稿（`我实测了 DeepSeek V4 Flash…`，缺"刚发布两天，"前缀）已精确删除。
  - 中等⑥：SOP/记忆与现状不符 → 已更新。
  - 轻微（暂留，可暂缓）：缓存按文件名跨文章串图、img 正则只认 src 首个属性（已顺手修）、无 alt、box-shadow/linear-gradient 未警告（已加警告）、凭据明文、单行文件 git diff 失效。
