# 8.3 AI工具链收口与自媒体内容生产 — 执行规划

> 本笔记由用户 8/3 日记中的口语化、跳跃式记录（剪脚指甲、找 Token、折腾 Heamos、Deepseek 惊艳、Codex 加加、远程装腾讯云等"口水话"）整理而成，目的是让**电脑上的 AI agent 能直接接力执行**。
> 凡标注【待用户确认】的，agent 执行前必须先向用户索取，不要臆造。

## 背景（口水话 → 核心意图）

用户 8/3 全天在折腾 AI 工具链，本质是三件事（按价值排序）：

1. **被 Deepseek V4 Flash 的"主动性"惊艳**（凌晨实战），想把这套经验写成文章、多平台分发。
2. **想收口 AI 工具链**：把所有第三方模型/中转站账号汇总，做到"一个 API 无限切模型"，消除"找 Token 的时间比用 Token 的时间都多"的痛点。
3. **想把内容生产流水线化**（公众号/推特/小红书），并探索 AI 文字转视频。

---

## 任务一：模型聚合（P0，最高优先，其他任务的前置）

**目标**：把所有第三方模型/中转站账号汇总，在 Codex（或"派"）里配一个 API，实现无限切换模型。

**已知信息（来自日记）**：
- 工具：Codex 加加插件（"安装 Codex 加加插件，把所有的第三方模型配置进去，方便的切模型"）
- 已有中转站/聚合端点：Codex 加加、Meta API、cPA（聚合）等
- 用户还有大量"白嫖中转站账号"待汇总（"把所有的中转站白嫖的账号汇总一下，方便在 Codex 里面显示"）
- 最终需求原话："在 Codex 或者派里面可以添加一个 API，能够无限切换第三方模型"

**执行步骤（供接力 agent）**：
1. 【待用户确认】向用户索取全部模型端点与 key（脱敏，走安全方式，**禁止经聊天明文传输**）。
2. 在 Codex 加加中配置这些端点。
3. 验证模型列表可正常切换、调用。
4. 评估"派"能否从 Codex 加加导入配置，方便统一调取。
5. 输出一份"模型资产清单"（端点、可用模型、备注），回写本笔记。

**风险**：涉及 key/token，务必走本地文件/环境变量，绝不通过第三方聊天泄露。

---

## 任务二：自媒体内容生产流水线（P1）

**素材来源**：今天 Deepseek V4 Flash 的两个"惊艳"实战点（见下方【素材库】）。

**用户口述的工作流（12:23）**：
1. 口述模糊概念
2. 发给 Deepseek 实战对话，让它讲清"当时如何博弈决策、为何在缺指令时精准把握需求"
3. 总结内容
4. 转成公众号文章（如何写、如何截图取图）
5. 执行完成后 Vivo 检查
6. 分发：公众号、推特、小红书

**排版**：用 `gzh-design skill`（用户原话"公众号排版是？skill"）。
**分发自动化**：用户已找到一个 SQL（"派班的 SQL 已经找到了一个"），但自动化发布尚未解决，需研究。
**延伸**：AI 文字转视频（文字转语音 / 真人语音），后续细化。

### 【素材库】供写文章用（来自 8/3 凌晨日记）

**惊艳点 A — 主动性探索**：用户在本地 NAS 让 Deepseek 执行长任务，只说"我有很多服务器"，没给任何配置。Deepseek 跑在一个子目录（按理应拿不到上级目录权限），却主动向上探索、抓到所有服务器的内存占用情况，并指出用户口述的"剩余 1.5G"实际只有约 0.5G（含唯一较大的 4G 腾讯云）。

**惊艳点 B — 自主补救**：
- 规划时用户漏给一个参数，退出 Plan 模式执行后，Deepseek 发现疏漏，主动查找丢失参数并在当前服务器内寻找补救措施，最终完成任务。
- 另一次部署 Hermes 外置系统时，用户没搞清楚是否需要 APIK 也没提供；Deepseek 执行时发现缺 APIK，自行在 NAS 里找到之前部署的 Meta API 中一个可用的 key，接到了新系统上。

**用户评价原文转意**："先规划后执行，真的有当初用 GPT 5.4 的惊艳感""yyds""不敢想 V4 Pro 能力会不会直接击穿那些高傲的前沿 AI 厂商"。

---

## 任务三：远程部署（P2）

**目标**：把 Codex 或"派"装到 4G 腾讯云，支持电脑/手机远程访问。

**待决策（用户口述）**：
- 远程方案选哪个方便（电脑端、手机端）
- 如何修改 API
- 本地已部署的 Meta API，如何让云服务器调用：**直连本地 NAS vs 云上重部署**

**⚠️ 安全红线**：避免公网直接暴露 NAS。建议参考库内 `4.30 Cloudflare Tunnel 0基础手动安装教程`，用 **Cloudflare Tunnel 反向隧道**（不开端口、带鉴权）让云安全调用本地 Meta API。

**依赖**：任务一（模型聚合）先落地。

---

## 任务四：环境资产沉淀 — 服务器/电脑参数写入系统提示词

**来源（01:50 口述）**："这么多服务器，改天了帮我搜一搜服务器配置信息，然后电脑上面参数 Windows WCR。这些东西完全可以写到系统提示词当中啊，我都给忘了。"

**执行**：
1. 汇总用户所有服务器的配置信息（型号、内存、角色、IP/域名等，脱敏）。
2. 汇总电脑端参数（Windows WCR 等相关配置）。
3. 整理成可注入"系统提示词"的结构化段落，供后续 agent 会话直接调用。

**优先级**：低于前三，但属于"一次沉淀、长期受益"的资产。

## 给接力 AI agent 的执行指引

1. **优先级**：任务一 > 任务二 > 任务三；任务四 穿插沉淀。
2. **先澄清再动手**：任务一、任务四 依赖用户资产（端点/key/配置），【待用户确认】项必须拿到再执行，禁止臆造。
3. **安全铁律**：所有 key/token 走本地文件或环境变量，绝不通过聊天明文传输。
4. **每完成一步**，回写进度到本笔记对应任务下（status / 输出物）。
5. **远程部署默认 Cloudflare Tunnel**，禁止公网直连 NAS。
6. **内容生产先用"惊艳点 A/B"素材跑通一篇公众号文章**验证流水线，再扩展多平台。
7. 遇到库内已有相关笔记（如 `4.30 Cloudflare Tunnel`、`5.8 JP NAS 本地部署 Kimi GLM 统一网关`）优先复用，不重复造轮子。
