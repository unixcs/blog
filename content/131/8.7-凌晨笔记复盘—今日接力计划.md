## 8.7 凌晨笔记复盘 — 今日接力计划

> 本笔记总结 `50_日记/2026年08月07日.md` 的凌晨段（00:07–00:23），主题是**两套工作流架构梳理 + 公众号自动化双方案设计 + CDN 痛点**。
> 第一性原理：分层处理——纯文本全自动（手机即可）、教程类需电脑实战；多端输入统一沉淀到 200 Wiki 再生成周/月/年总结。
> 标注【待确认】的必须先向用户索取，禁止臆造。

## 一、凌晨日记要点总结（00:07–00:23，口述 → 要点）

### 1. 第一套工作流（已运行数月，现状）
- 多端输入：手机 WPS（日记/碎片口水话）→ 安卓同步服务器 → NAS + Windows；电脑端浏览器插件剪切到检查目录；NAS 端交给 Hermes 沉淀到 200 Wiki。
- Hermes 角色：从口水话日记/口述里**提取 plan（明日计划），按重要程度排序成待办表**。
- 沉淀路径：每天笔记 → 200 Wiki 规则 → 后续周记/月记/年度总结。

### 2. 第二套工作流：公众号自动化（双方案设计）
- **方案 A（全自动·纯文本）**：口述→碎片/灵感目录→简单搜索拼接初稿→去 AI 味写作生成最终纯文字稿→封面图（不开电脑则默认图/随机预设图）→排版 Skill→推送公众号草稿箱→审核发送。后期手机 Telegram 给 Hermes 发消息即可直接生成+推送。
- **方案 B（精益求精·教程/长文）**：口述开头结尾→Obsidian→Telegram 给 Hermes 看灵感→润色开头标题→初稿（中间留占位符）→开电脑实战→总结填入占位符+加图→图片粘贴 Obsidian 自动转阿里云 OSS 图床 URL→MCP Push 开源插件推送。后期给 MCP Push 加 Python Script 功能 + 改 CSS 主题（当前太大、不清爽）。

### 3. CDN 痛点（额外）
- 痛点1：左侧目录多层嵌套，切深目录要点多次。需首页路由主页，常用目录（日记/剪藏/动画笔记）按最新时间清晰展示。
- 痛点2：在编辑器中想把左侧预览文章拖拽到命令行（cMI）拖不过去，现有插件不好用。

## 二、第一性原理：分层与注意力

| 层 | 真相 |
| --- | --- |
| 内容分层 | 纯文本感悟=全自动（手机）；教程实战=需电脑；不混为一谈 |
| 输入统一 | 多端（手机/电脑/NAS）→ 统一沉淀 200 Wiki → 周/月/年总结 |
| 稀缺资源 | 注意力；自动化消除生产摩擦，实战留给高价值长文 |
| 安全底线 | OSS 图床/公众号 secret 走本地/环境变量，勿聊天明文 |
