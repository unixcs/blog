# YoShop服务订单权限、版权移除与WSL云端发布收口

## 时间

- 2026-07-16（Asia/Shanghai）

## 用户目标

1. 修复新建管理员 `guanxing`（归属“运营和客服”角色组）在商家后台操作服务类订单时的权限问题：
   - “开始服务”按钮缺失；
   - “开始服务”接口曾提示无权访问 `order.event/startService`；
   - “服务前退款”接口提示无权访问 `order.event/refundBeforeService`；
   - 同时补齐“完成服务”能力权限。
2. 移除商家后台所有页面底部固定版权声明：
   - `Copyright © 2024 萤火商城V2.0 YIOVO.COM`
3. 校正开发上线工作流，明确 WSL 本地验收、GitHub 推送和腾讯云生产部署不是同一阶段。
4. 在 WSL 验收通过后，将代码推送 GitHub，再通过受保护发布工具部署腾讯云生产。
5. 完成 Trellis 任务收口，并保存本次对话总结。

## 背景与上下文

系统原本是实物商城，权限菜单和订单操作围绕“发货、确认收货、订单导出”等实物履约动作建立。系统改造成服务类商品并接入微信虚拟支付后，商家后台改为“开始服务、完成服务、服务前退款”等操作，但权限菜单、API 权限和角色授权没有同步补齐。

因此，旧管理员可能因历史权限数据偶然可操作，而新建管理员即使勾选“订单处理”，也无法调用新服务接口。前端还使用了旧权限作为回退，导致显示逻辑与后端实际授权不一致。

## 根因与关键决策

### 服务订单权限根因

- 新接口已经存在，但没有完整挂接到可分配的菜单权限能力。
- 角色权限数据实际保存的是叶子权限，不一定直接保存 `/order/tools` 父菜单。
- `guanxing` 所属角色 `运营人员(10001)` 持有旧的直接子权限 `订单导出(10202)`，而非最初假设的父权限 `10201`。
- 因此前一版仅按父权限迁移角色授权的方案不完整，必须同时识别“拥有父菜单”或“拥有父菜单下任一直接子权限”的角色。

### 权限迁移设计

新增三个前端能力权限：

```text
/order/tools.startService
/order/tools.completeService
/order/tools.refundBeforeService
```

分别绑定后端 API：

```text
/order.event/startService
/order.event/completeService
/order.event/refundBeforeService
```

迁移采用以下约束：

- 通过 URL/语义解析 `/order/tools` 和订单 API 父节点，不硬编码依赖固定 ID；
- 父节点缺失或解析结果不唯一时，通过 `SIGNAL` 主动失败，禁止静默写错权限树；
- 新菜单/API ID 使用 `AUTO_INCREMENT`，不使用有并发风险的 `MAX(id)+1`；
- 脚本支持重复执行，保证幂等；
- 只给符合历史订单处理权限条件的角色补齐新服务权限；
- 保留旧权限数据用于兼容和回滚，但前端不再以旧实物权限作为服务操作回退。

### 上线工作流校正

最终确认的标准流程：

```text
修改代码
→ 自动化检查
→ WSL 本地部署
→ 用户手动验收
→ Git commit/push
→ 生产 preflight/dry-run
→ 生产授权
→ 腾讯云正式发布
→ 生产验证
```

“生产部署”明确指腾讯云服务器，不是 WSL。本地源码修改后如果需要用户马上验证，必须先将构建产物同步到 WSL 正在运行的 Web 根目录，并按变更类型清缓存、重启或重载相关服务。
