## 3. 铁律（hermes 必须遵守）

1. **单推送出口**：微信副作用（建草稿/传素材）只允许经 peterpan 的 `publish-file` / `upload-cover` / `upload-image`。禁止 md2wechat `--upload/--draft`、禁止手写 curl 调微信 API（排除障探测）。
2. **排版合规门**：交付 HTML 必须 **0 ERROR**（validate_gzh_html.py）+ 全路径 `{{占位符}}` 硬门（check_placeholder.sh）过关。不得跳过。
3. **封面必填**：`publish-file --thumb` **只接受本地图片文件路径**（peterpan 内部 `existsSync` 判断；传 media_id 字符串 → 静默回退成首张正文图或空 → 40007/40013）。封面 jpg 路径直接传 `--thumb`，peterpan 自动上传并按文件 hash 去重缓存（`upload-cover` 提前传也无害但非必需）。
4. **去AI味必做**：正式发文前必须 `md2wechat humanize <draft.md>`（**等号形式**）取回 prompt 由 LLM 执行后合并。

## 4. 标准执行步骤（默认路线，逐条命令）

### Step 1 写稿
- 产出 Markdown 初稿到 hermes 可写目录（如 `/opt/data/工作流/_tmp/`，或 `/tmp`）。
- 初稿先发用户确认（铁律5）。
- **正文（含代码示例）不要出现 `{{作者名}}`/`{{简介}}` 这两个保留 token**，示例占位请改写为 `{{cmd}}` 之类一般 token。

### Step 2 去AI味
```bash
md2wechat humanize 稿子.md --intensity=medium
```
> **必须等号形式**。空格形式 `--intensity medium` 会报 `accepts 1 arg(s), received 2`。
> 解析 JSON：`status=="action_required"` 时取 `data.request.content`，LLM 按 prompt 重写正文，写回 `稿子.humanized.md`。
> **必须检查 `success`/`status` 字段，`success!=true` 视为失败（进程可能 exit 0）**。

### Step 3 排版
默认固定CSS确定性渲染：
```bash
/opt/hermes/.venv/bin/python /opt/data/skills/wechat-publish-workflow/scripts/render_fixed.py <稿.md> --out <dir> --name <名> [--author 作者名] [--intro 简介]
```
- 产物命名：`{名}_排版_固定商务(fixed-business).html`
- 自带 validate 0 ERROR + check_placeholder.sh 自检
- 占位符 `{{作者名}}`/`{{简介}}` 未传对应参数 → fail-fast 退出、不产出文件
- 用户消息中出现 `skill排版` / `用skill` → 走 gzh-design skill（产物同样要过硬门）

### Step 4 合规门
- render_fixed 产物自带；gzh-design 路径产物手动补跑：
```bash
bash /opt/data/skills/wechat-publish-workflow/scripts/check_placeholder.sh <产物.html>
```
- `validate_gzh_html.py` 校验：报 ERROR 必须回头修。

### Step 5 封面（三分支）
前置：凭证 `/opt/data/.wechat-publisher/stepfun.json`。
```bash
# 统一格式（务必带 --out/--name，默认会写 /tmp/gzh_cover_out/cover_*.jpg 也好用但建议显式）
/opt/hermes/.venv/bin/python .../gzh_cover.py --out <dir> --name <名> --hint "<一句话概要>"          # 默认：无文字+moren
/opt/hermes/.venv/bin/python .../gzh_cover.py --out <dir> --name <名> --text "<文字>"                 # 文字+moren
/opt/hermes/.venv/bin/python .../gzh_cover.py --out <dir> --name <名> --text ... --style minimal      # 文字+风格
/opt/hermes/.venv/bin/python .../gzh_cover.py --out <dir> --name <名> --style minimal...             # 无文字+风格
/opt/hermes/.venv/bin/python .../gzh_cover.py --out <dir> --name <名> --image <图>                    # 用户给图归一化
```
- 输出 `<out>/<name>_{no-text|with-text|user-image}.jpg`（900x383 ≤1MB）
- styles：`minimal/tech/oilpaint/watercolor/ink/vintage`（acts >moren 默认）
- **带文字封面必须先发用户人工确认**，确认后才准上传+发布；超时未回复默认中止（带文字 15 分钟 / 无文字 10 分钟）
- **`--hint` 仅对「无文字 + moren」档生效**——带文字档 hint 被静默忽略
- 图片放 hermes 可写目录，必须本地磁盘文件

### Step 6 推送（推草稿箱）
```bash
export WECHAT_PUBLISHER_DATA_DIR=/opt/data/.wechat-publisher
node /opt/data/skills/wechat-publisher/wechat-publisher.mjs publish-file <html> \
  --thumb <封面本地路径>.jpg --title <标题> --digest <摘要> --author <作者>
```
> **三条硬约束**：
> 1. `--thumb` 传**本地封面 jpg 路径**（铁律3）
> 2. **必须显式 `--title/--digest`**：render_fixed 产物的 h1 被 `<span leaf>` 包裹，peterpan 提取不出 → 不传会产出 **"Untitled"** 草稿（已实测证实）
> 3. **`--dry-run` 不是零副作用**：新图仍会上传占素材配额（上传发生在 dryRun 判定之前）；长文预览截断为前 800 字符 —— 预览建议用 `convert`，dry-run 仅作冒烟

### Step 7 回报
- 给用户 media_id + 草稿标题，提示"已入草稿箱，请到公众号后台手动群发"
- 发布前 round-trip 回读校验标题，确认非 "Untitled"

## 5. 封面生成内部参数（gzh_cover.py，调用者无需关心）

- **API size 转置（实测）**：请求 `768x1360` 才返回横版 `1360x768`；请求 `1360x768` 返回竖版。脚本内已固化 `REQ_SIZE="768x1360"`。
- 目标 900x383（2.35:1，微信首图标准）≤1MB；quality high，超限循环降 q 到 ≤40 止
- 裁剪：宽/高≥2.35 沿宽居中裁，否则沿高居中裁；绝不非等比缩放
- 用户图归一化：宽>1360 限宽；竖图 WARN 提示确认；超 2.35:1 裁剪
- 失败回退链：生图失败 用户指定图 → 正文首图 → 均无则中止告知，不建草稿
- 重试：脚本内 1 次重试（共 2 次尝试）

## 6. 错误码速查（微信 API + 脚本 EC-）

| 错误码 | 含义 | 处置 |
|---|---|---|
| 40001 | access_token 无效/不是最新 | 删 `/opt/data/.wechat-publisher/token.json` 后重试（多客户端并发刷新互作废） |
| 40014 | token 过期 | 同上，重新 auth |
| 40164 | 出口 IP 不在白名单 | 不要反复重试；引导用户后台加白名单 |
| 40013 | 参数错误（常见：缺封面 thumb） | 补 `--thumb`（**传本地文件**）后再试 |
| **40007** | **invalid media_id（最常见踩坑）** | thumb 传了 media_id 字符串或空 → 改传本地封面路径 |
| 42001 | token 刷新过于频繁 | 等待 1 分钟 |
| 48001 | 个人号无 freepublish 权限 | 属正常，只能建草稿人工群发（publish 命令对它永远 48001 且 exit 0） |
| 45009 | API 调用超限 | 等待配额恢复 |
| EC-001 | 生图失败（网络/超时/配额/qualit
