> 对话笔记直发：5.12 使用 oh-my-opencode-slim 开发小程序。分类：小程序接单。

你已经有 `PRD.md`、`API.md`、`数据库设计.md` 这些文档了，配合这个插件的工作流如下：

**1. 在 `mini` 目录下打开 OpenCode**

```bash
cd D:\Program\0\home\0\mini
opencode
```

插件会激活全部 Pantheon agent，`orchestrator` 就是你现在的对话代理。

**2. 让 orchestrator 自动调度**

你直接说需求，它会自动决定：
- **explorer** → 帮你扫一遍项目现有文件
- **librarian** → 查小程序开发框架的最新文档
- **oracle** → 审查你写的架构/设计是否合理
- **designer** → 处理 UI 代码
- **fixer** → 写具体的工具函数、测试

例如：
```
帮我根据 PRD.md 搭建小程序项目结构
```

orchestrator 会自动把任务拆给对应的 agent。

**3. 手动调特定 agent（当你明确要谁干活时）**

在聊天框里直接：
```
@explorer 看一下当前项目的文件结构
@oracle 帮我评估这个数据库设计的合理性
@designer 根据 PRD 生成首页的 wxml 和 wxss
@fixer 帮我写这个工具函数的单元测试
@librarian 查一下 TDesign 小程序组件库的最新用法
@council 对比一下 Vue 和 React 小程序方案的优劣
```

**4. 一个典型的小程序开发流程**

```
① @explorer 扫描项目结构并总结现状
② 你开始提功能需求，orchestrator 自动调度 agent
③ @oracle 帮你做关键设计决策
④ @designer 处理页面 UI
⑤ @fixer 写业务逻辑和测试
```

**5. 关键用法技巧**

| 场景                    | 怎么做                                                  |
| --------------------- | ---------------------------------------------------- |
| 想让 orchestrator 自动分配  | 直接说需求就行                                              |
| 想指定谁干活                | `@agentName <任务>`                                    |
| 改模型预设                 | 编辑 `oh-my-opencode-slim.json` 里的 preset              |
| 切到 opencode-go preset | 把 `"preset": "default"` 改成 `"preset": "opencode-go"` |

**你现在可以直接做的一步**

在 `mini` 目录下运行：
```bash
opencode
```

然后发一条：
```
根据 PRD.md 和 API.md，帮我分析这个小程序的整体架构，给出项目和目录结构建议
```

orchestrator 会自动协调 explorer（看文件）→ oracle（分析架构）→ 返回结果给你。


**3. 使用智能体**  
配置完成后，在 OpenCode 的输入框中，你可以通过 `@` 符号直接呼出不同角色来指派任务，例如：

- `@explorer 帮我找到项目中所有与支付相关的代码`
    
- `@designer 重构一下购物车主页面的样式，让它更现代一些`
    
- `@oracle 审查一下新写的订单处理模块，看看有没有潜在的并发问题`
    

如果需要处理更复杂的任务，也可以直接向 `Orchestrator` 下达一个宏观指令，它会自动将任务拆解并分派给合适的智能体去完成[](https://github.com/alvinunreal/oh-my-opencode-slim)。

### 💡 进阶技巧

掌握以下几个关键工作流，能极大提升你的开发效率：

- **📋 结构化需求（Interview）**：如果你的想法还有些模糊，可以使用 `@orchestrator` 并提及“interview”功能，它会通过问答的方式，帮你将粗糙的想法逐步梳理成一份结构清晰、可直接执行的 Markdown 格式需求文档[](https://github.com/alvinunreal/oh-my-opencode-slim)。
    
- **🤯 头脑风暴（Council）**：当你面临技术方案选型、架构设计等难题时，可以使用 `@council` 功能。它会同时让多个模型并行思考，并将它们的回答整合成一份全面的报告，供你决策参考[](https://github.com/alvinunreal/oh-my-opencode-slim)。
    
- **🗺️ 代码地图（Codemap）**：刚接手一个新项目，或者项目代码庞大不知从何下手时，可以借助 `codemap` 功能。它能快速生成一个层次化的代码结构地图，帮你迅速理解整个项目的架构[](https://github.com/alvinunreal/oh-my-opencode-slim)。
    
- **💾 会话复用（Session Management）**：你可以保存和复用某个智能体的会话上下文，避免重复沟通，特别适合需要多次迭代的长期开发任务[](https://github.com/alvinunreal/oh-my-opencode-slim)。
    

### 💎 针对你的微信商城项目，上手即用的策略

基于你的微信商城项目，我为你梳理了一个结合 oh-my-opencode-slim 的开发路径：

1. **从模糊到清晰（结构化需求）**  
    如果感觉PRD文档还不够详尽，别担心。直接对 `orchestrator` 说：“`@orchestrator`，我有一份关于微信商城小程序的PRD文档，但不够详细，请通过‘interview’流程，帮我把它完善成一份包含页面结构、数据模型和接口定义的完整技术规格文档。”
    
2. **技术选型（头脑风暴）**  
    在开始编码前，可以利用 `@council` 功能来解决关键的技术选型问题。例如，你可以问：“`@council`，对于这个微信商城项目，支付模块应该用微信原生支付还是第三方聚合支付？后端用云函数还是自建服务器？请帮我分析一下各自的利弊。”
    
3. **分派任务（专人专事）**  
    根据我们在上一轮讨论的开发顺序，你可以为每个阶段分配合适的智能体：
    
    - **阶段0 (环境搭建)**：`@orchestrator 根据技术规格，使用 uni-app 框架为我初始化一个可直接运行的微信商城小程序空壳项目，并配置好微信云开发环境。`
        
    - **阶段1 (后端与接口)**：`@orchestrator 根据规格文档，为我生成所有云函数（如getGoodsList, createOrder, wxPay等）的代码骨架和数据库集合的创建脚本。`
        
    - **阶段2 (前端页面)**：`@designer 根据规格文档的设计要求，生成商城首页、商品详情页、购物车页和个人中心页的代码。`
        
    - **阶段3 (核心业务)**：`@orchestrator 现在，实现微信支付功能。请协调所有必要的智能体，完成从创建订单、调用支付到处理支付回调的完整流程，并确保对库存的超卖、支付超时等异常情况有完善的处理。`
        

如果你在某个具体步骤上遇到问题，随时可以再问我。
