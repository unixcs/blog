# 8.3 AI工具链收口与自媒体内容生产 — 123阶段执行规划

> 按 [[200_Rules/工作流/想法驱动执行体系|想法驱动执行体系]] 整理。
> 核心真问题：稀缺资源是"想法→成果"之间的注意力；四件事 = 消除四层摩擦。
> 标注【待确认】的必须先向用户索取，禁止臆造。

## 0. 第一性原理与排序结论

- 排序：**价值层（阶段1）→ 支撑层（阶段2、3）→ 延展层（阶段4）**
- 阶段1 不依赖任何前置，立即可做；阶段4 依赖阶段2。

| 阶段  | 成果                | 消除的摩擦 | 类型  |
| --- | ----------------- | ----- | --- |
| 1   | 用惊艳点A/B出一篇可发公众号文章 | 生产摩擦  | 价值层 |
| 2   | 1个稳定聚合端点+验证切模型    | 工具摩擦  | 支撑层 |
| 3   | 环境资产写入系统提示词       | 记忆摩擦  | 支撑层 |
| 4   | 4G腾讯云远程访问         | 位置摩擦  | 延展层 |

**今日验收标准**：阶段1 文章可发；阶段2 端点可切模型；阶段3 资产段可注入；阶段4 方案已定。

### 1.6.1 ✅【已沉淀】微信渲染引擎兼容修复（2026-08-04）

**根因**：微信 API 存储 HTML 几乎原样保留（draft/get 对比仅 `display:block` 5 处被删，flex/gap/overflow-x/box-shadow/border-radius/linear-gradient/svg 计数全同）→ 问题出在**公众号编辑器/预览渲染内核（老 WebView）**不认某些写法。

**症状 → 写法映射**：
- 目录 4 卡横向滚动失效、卡片变宽 → `overflow-x:scroll` + `white-space:nowrap` + `inline-block` 横排
- 浅绿虚线框消失 → 嵌套 `<section>` 的 `border:1px dashed`
- 封面底条按钮圆角/留白被删、两侧留白 → `display:flex;justify-content:space-between` + `rgba()`
- 绿色短横线消失、标题间距乱 → 空 `<section width:48px;height:3px>` 装饰元素

**修复原则（已写入 `gzh-design/references/theme-moyu-green.md` 铁律 + `validate_gzh_html.py` RISKY WARNING 规则）**：
- ❌ 弃用 `display:flex`/`gap`/`flex:1`/`justify-content` → ✅ 横排用 `<table>`（最稳）或 `inline-block` + `margin`
- ❌ 弃用横向滚动目录 → ✅ 2×2 `<table>` 网格目录（组件 3 toc-grid）
- ❌ 弃用空装饰 `<section>` → ✅ 带内容的 `<p>`（`&nbsp;` + `line-height` 撑高），或并入相邻元素 `border-bottom`
- ❌ 弃用嵌套 section `dashed` 边框 → ✅ 单层 section 实色背景 + `border-left` 左竖条（组件 9a/9b）
- ❌ 弃用 `rgba()` 半透明 → ✅ 实色；❌ 弃用 `<svg>` → ✅ emoji/文字（footer 三连）
- ⚠️ 升级后的校验脚本对上述 8 类写法报 WARNING（命中即提示改 table/实色），旧版 HTML 回归测试命中 89 处

**涉及文件**：`theme-moyu-green.md`、`common-components.md`（1a 代码块顶栏 flex）、`validate_gzh_html.py`、本文排版 HTML 重排

> ⚠️ **待用户确认**：上述修复版（lcYb1T）的渲染正确性尚未在微信编辑器实测——之前"仍看到旧问题"实为打开了未更新的旧草稿，需用户打开唯一草稿 `lcYb1T` 复核后再发布。
