# 8.9 首页导航路由改造（apex-dashboard 版）

## 需求
每次打开 Obsidian 需要手动逐级展开左侧文件树找每日文件，痛点：缺少"一键直达最新内容"的入口。

规则：按高频目录自动路由到最新一天文件（今天有→今天；无→前推一天→最新）。

高频目录：01 工作台、300 日记、50 原始日记、20 对话笔记、30 剪藏、40 碎片、10 项目（公众号/物业/小程序）、100 Wiki、200 Rules。

## 方案决策
- ~~改造旧 `首页导航.md`（dataviewjs 版）~~ 被否决（用户选 apex-dashboard）
- **使用 apex-dashboard v1.6.2** 作为可视化首页外壳 + **Homepage 插件**启动自动打开

### 关键架构发现
1. apex-dashboard 是"数据驱动可视化外壳"，解析 `dashboard.md` 的 YAML frontmatter + `## 分区名` 标题，**不执行 dataview/dataviewjs**。
2. 实现"今天→昨天→最新"回退的机制：**library 分区**（文件夹扫描）+ **sortBy: name/modified + sortDesc: true**。排序顶部 = 最新一天文件。点卡即路由。
3. 文件夹型 quickActions `type:file` 对文件夹路径无效（`navigateToPath` 只聚焦文件树，不选中/展开，且可能误开同名文件）—— 已全部删除，改用 library 列。
4. Homepage 插件 v4.4.4 支持命令模式：`homepage.data.commands = [{id:"apex-dashboard:open-dashboard", period:"Startup only"}]`，结合 `kind:"Nothing"` 不产生多余 markdown tab。

### 审核历程
- **架构评审 FAIL**（初次）：修正了 `section:` 字段→`library:`、排序策略（01 工作台用 name，其余用 modified）、删除文件型 quickActions
- **架构评审 PASS**（REV2）：修正后通过
- **代码复核通过**：dashboard.md 11 列 schema 验证通过（无 section、library 嵌套正确、## 与列 name 一致、10 个文件夹路径皆存在）

## 实施产物

### dashboard.md（库根）
11 列 library 分区、1 个 quickAction（新建日记）:
1. `01 工作台` — sortBy: name desc（日期零填充文件）
2. `300 日记` / `50 原始日记` / `20 对话笔记` / `30 剪藏` / `40 碎片` — sortBy: modified desc
3. `项目·公众号` / `项目·物业` / `项目·小程序` — sortBy: modified desc
4. `100 Wiki` / `200 Rules` — sortBy: modified desc

### 插件配置
- apex-dashboard 升级到 v1.6.2，data.json: dashboardFile:"dashboard"
- Homepage 插件 v4.4.4 下载安装，data.json 配置 kind:"Nothing" + commands open-dashboard
- community-plugins.json 启用 apex-dashboard + homepage

### 归档
- `首页导航.md`（旧 dataview 版）→ `90_历史归档/首页导航_旧版_2026-08-09.md`
- `200_Rules/首页导航说明.md` 追加新首页入口说明
- 3 个规则文档更新引用（每日工作流/全览流程图/目录结构）

# 发现的问题
