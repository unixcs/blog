## 端到端验证与权限问题排查（完成）

### 发现的重要架构事实
- `get_hermes_home()` 读 `HERMES_HOME` env 或 `Path.home()/.hermes`；gateway 用 `HERMES_HOME=/opt/data`（systemd hermes-gateway.service），**CLI 以 root 跑会读 /root/.hermes**（空）导致「No scheduled jobs」
- 正确手动操作：`su - hermes` 或 `HERMES_HOME=/opt/data ... cron run 9eadb723492b`

### 权限问题（重要）
- 用 root 编辑 jobs.json 后 owner 变 root:root 600 → gateway(hermes) 每 tick `Permission denied`，cron 空转、手动触发被吞
- 修复：`chown hermes:hermes /opt/data/cron/jobs.json && chmod 644`
- **教训：Hermes CLI 操作必须用 hermes 用户 + HERMES_HOME，勿用 root**（root 跑 CLI save_jobs 会把文件 owner 改回 root）
- `.apitoken`（root:root 600）hermes 读不了 → Hermes agent 改走 `chown hermes:hermes` + 600（token 仍在本地文件，不违反红线）；agent 实测还聪明地改用 Vikunja SQLite 直查
